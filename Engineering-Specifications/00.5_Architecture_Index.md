## 1. Introduction

### 1.1 Purpose

This **Architecture Index / Enterprise Knowledge Index** is the **central navigation and linking hub** of the AssetX documentation set. It enables any engineer, tester, or AI model to locate and trace any element — a requirement, business rule, entity, table, API, workflow, screen, test, or event — **from a single place**.

It **creates no new content**. It unifies linking between all documents by:

1. Registering every **document** with a unique `DOC-xx` identifier.
2. Defining the **global ID scheme** (approved `ADL-X-06`) used across all documents.
3. Establishing the **traceability rules** every document must follow (approved `ADL-X-07`).
4. Providing the **central element registry** that is **populated incrementally** as each document is completed.

### 1.2 Status

- **Approved:** ID scheme, traceability rules, and the role of this hub.
- **Incremental:** The central element registry (§5) grows as Engineering Specifications 01–15 are produced.

## 3. Global ID Scheme (Approved — ADL-X-06)

Every identifiable element in the project carries a unique ID from the scheme below. Existing types are canonical; new types are approved.

### 3.1 ID Scheme

| Type | Prefix / Format | Example | Authoritative Source |
|---|---|---|---|
| **Document** | `DOC-NN` | `DOC-08` | Architecture Index §2 (this document) |
| **System Module** | `MOD-NN` | `MOD-03` | Module registry (AAB §13.13 — 20 modules) |
| **Business Rule** | `BR-XXX-NNN` | `BR-ASSET-001` | AAB §13.1; Business Rules Catalog (02) |
| **Functional Requirement** | `FR-XXX-NNN` | `FR-ASSET-002` | FRS |
| **Non-Functional Requirement** | `NFR-XXX-NNN` | `NFR-PRF-001` | NFR |
| **Decision** | `ADL-XXX` | `ADL-001`, `ADL-X-06` | Documentation Audit & Decision Log (00) |
| **Bounded Context** | `BC-XXX` | `BC-INVENTORY` | SAD §5.2 |
| **Entity** | `ENT-XXX` | `ENT-ASSET` | Entity Specifications (01) |
| **Table** | `TB-XXX` | `TB_ASSET` | DDS; Data Dictionary (04) |
| **Field / Column** | `FLD-XXX` | `FLD_ASSET_FULLCODE` | Data Dictionary (04) |
| **API Endpoint** | `EP-XXX` | `EP-ASSET-CREATE` | API Contracts (07); API Spec |
| **Screen** | `SCR-XXX` | `SCR-INV-CYCLE` | UI/UX; Entity Specifications (01) |
| **Workflow** | `WF-XXX` | `WF-INV-CYCLE` | Workflow Specifications (06) |
| **Test Case** | `TC-XXX` | `TC-ASSET-CREATE-01` | Test Strategy; Traceability Matrix (final) |
| **Event** | `EV-XXX` | `EV-ASSET-CREATED` | SAD; Entity Specifications (01) |

### 3.2 Naming Rules

- Prefixes are **UPPERCASE**; the suffix is context-specific.
- `XXX` segment identifies the owning area (module / context / domain), `NNN` is a zero-padded or logical number.
- IDs are **stable and immutable** once assigned.
- New IDs are assigned in the owning document and **registered in the Architecture Index** incrementally.
- IDs must be referenced (not redefined) across documents for traceability.

## 4. Traceability Rules (Approved — ADL-X-07)

These rules are **mandatory** for every AssetX document:

1. **Every document** carries a `DOC-xx` ID and a `References` section.
2. **Every element** (module, entity, table, field, API, screen, workflow, test, event, requirement, rule, decision) is assigned an ID from §3 **in its owning document**.
3. **Each document** includes the four linking sections: `References`, `Related Documents`, `Dependencies`, `Traceability`.
4. **Traceability** in each document maps its elements to source requirements (BR/FR/NFR) and downstream artifacts (design/test/build).
5. **No duplication:** elements are defined once (in their owning document) and referenced elsewhere.
6. **No redefinition:** existing IDs (BR/FR/NFR/ADL) are referenced, never re-assigned.
7. **Incremental population:** as each document is completed, its elements are registered in the central registry (§5) and the (future) final Traceability Matrix.
8. **Pending decisions** are referenced by `ADL-xxx` and marked Pending — never resolved ad hoc.

## 7. Navigation & Maintenance

- **Single entry point:** This index is the first stop to find any document or element.
- **Adding a document:** assign the next `DOC-xx` ID, add to registry §2.
- **Adding an element:** assign ID in owning doc, register in §5.
- **Resolving a decision:** update the Decision Log (status Approved) and update this index's pending list.
- **Final matrix:** after Engineering Specifications 01–15 are approved, generate the consolidated Global Traceability Matrix from §5.
