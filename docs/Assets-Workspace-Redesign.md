# إعادة تصميم مساحة عمل الأصول

## القرار

تعالج الصفحة الجديدة مشكلة ازدحام جدول الأصول دون نقل واجهة WPF أو سلوكها التقني. الفكرة التي ثبتت فائدتها في النظام السابق هي فصل **اختيار الأصل** عن **تفاصيله وتحريره**، مع بحث ذكي وقائمة قريبة من المستخدم. أما التنفيذ الجديد فيبقى React/Next.js، ويستخدم العقود والصلاحيات وسجل التدقيق الحاليين.

| الملاحظة من النظام السابق | القرار في الواجهة الجديدة | سبب التكييف |
|---|---|---|
| بحث ذكي مع اقتراحات | حقل بحث واحد يبحث بالاسم والكود والرقم التسلسلي والباركود والموقع، مع قائمة نتائج مختصرة قابلة للاختيار. | يقلل الحاجة إلى فلاتر متناثرة قبل الوصول للسجل. |
| قائمة «آخر الأصول» | لوحة قائمة أصول قابلة للبحث، تعرض الاسم والكود والموقع والحالة والكمية. | القائمة ليست مجرد جدول؛ بل نقطة بدء للتنقل إلى سجل واحد. |
| نموذج دائم بجانب القائمة | لوحة تفاصيل أولاً، تتحول إلى تحرير عند الضغط على «تعديل». | يمنع فتح نافذة كبيرة لكل عملية استعراض ويحافظ على أمان التعديل. |
| أزرار جديدة/حفظ/نسخ/حذف/تراجع | شريط أوامر سياقي: «أصل جديد»، «تعديل»، «نسخ الأصل»، «تعديل جماعي»، و«استبعاد»، مع التراجع داخل نموذج التحرير. | تظهر الأوامر عند وجود سياق صحيح ولا تزدحم الشاشة. |
| تبويبات بيانات أساسية/مالية/إضافية | ملخص سريع في لوحة التفاصيل مع رابط صريح إلى سجل الأصل الكامل. | يحافظ على سرعة الاستعراض، بينما تبقى البيانات المتعمقة في صفحة التفاصيل الحالية. |

## الهيكل المقترح

على سطح المكتب تكون الصفحة مساحة عمل من عمودين، مع قائمة على اليمين في RTL بعرض تقريبي 360 بكسل، ولوحة تفاصيل مرنة إلى اليسار. رأس القائمة يحتوي البحث الذكي والإجراءات العامة، ثم نتائج قابلة للتمرير. عند اختيار عنصر تصبح لوحة التفاصيل هي الهدف البصري الرئيس وتعرض الهوية والموقع والحالة والقيمة والإجراءات المصرح بها.

على الهاتف لا تُعرض الأعمدة جنباً إلى جنب. تبدأ الصفحة بقائمة البحث والنتائج، ثم يفتح اختيار الأصل لوحة تفاصيل كاملة مع زر عودة. يبقى الإجراء الرئيس في أسفل منطقة العرض أو في شريط رأس ثابت، ولا يُستخدم نموذج مزدحم داخل نافذة لا تتسع للمحتوى.

> لا يدخل المستخدم وضع التحرير بمجرد اختيار سجل. يظهر الأصل أولاً في وضع قراءة آمن، ثم يضغط «تعديل» بقرار واضح. يقلل ذلك تغيير البيانات غير المقصود ويجعل «تراجع» ذا معنى عملي.

## قواعد التفاعل

| التفاعل | السلوك المطلوب |
|---|---|
| كتابة البحث | البحث بالاسم والكود والرقم التسلسلي والباركود، ثم عرض قائمة نتائج مختصرة مع الاسم والكود والموقع والحالة. |
| اختيار نتيجة | تحديث اللوحة بملخص الأصل المحدد، مع رابط واضح إلى صفحة التفاصيل الكاملة. |
| أصل جديد | يفتح نموذج الإدخال في وضع مخصص مع شريط حفظ واضح دائماً. |
| نسخ الأصل | يفتح النموذج ببيانات الأصل المحدد مع حذف المعرفات والأكواد التي لا يجوز تكرارها. |
| تعديل جماعي | لا يظهر إلا بعد اختيار سجل أو أكثر من القائمة، ويبقي العملية الحالية محكومة بالصلاحية. |
| محاولة مغادرة تحرير غير محفوظ | تظهر رسالة تأكيد قبل فقدان التغييرات. |
| حذف أو استبعاد | يبقى ناعماً ومحكوماً بالارتباطات والصلاحيات؛ لا يُضاف حذف مادي. |

## ما لا يُنقل

لا تنقل هذه الدفعة WPF أو SQL Server أو مفاتيح الاختصار المكتبية أو منطق SHA-256 القديم. كما لا تعرض قيمة دفترية أو إهلاكاً إلا عند توفر بيانات من عقد المنصة الحالي. الأثر المطلوب هو **سلاسة اختيار الأصل وفهمه والعمل عليه**، وليس مطابقة شكل الواجهة القديمة حرفياً.

## حدود الدفعة الحالية

تتضمن الدفعة المنفذة القائمة الذكية، لوحة الملخص، الانتقال المتجاوب للهاتف، وإجراءات التحرير والنسخ والحذف والتعديل الجماعي والاستبعاد المحكومة بالصلاحيات. أما الفرز الصريح، وطلبات تفاصيل موسعة عند اختيار كل سطر، وعرض تبويبات مستقلة داخل اللوحة، وتحذير مغادرة النموذج المتسخ، فتبقى تحسينات لاحقة ولا تُعرض على أنها مكتملة هنا.
