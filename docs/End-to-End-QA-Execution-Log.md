# سجل اختبار القبول التشغيلي — AssetX Enterprise Platform

**تاريخ التحقق:** 15 أغسطس 2026
**النطاق:** واجهة الويب Next.js، Backend NestJS، وعقد API وقاعدة بيانات PGlite المحلية.
**بيئة التحقق:** حساب المسؤول المحلي `admin`، بعد بناء حزمة الويب المستقلة وإعادة تشغيل الخدمتين على المنفذين 3000 و3001.

## ملخص النتيجة

اكتملت عملية تحقق تشغيلية متدرجة للمنصة، تبدأ من صفحات الواجهة وتدفقات المستخدم ثم تصل إلى واجهات API والتخزين المحلي واختبارات العزل والصلاحيات. نجحت جميع الاختبارات المجدولة بعد تقسيم اختبارات Backend إلى دفعات متتابعة لتفادي ضغط الذاكرة، كما نجحت حزمة الواجهة بالكامل وبناء Webpack الإنتاجي الذي ولّد 23 مساراً.

| مجال التحقق | النتيجة | الدليل التشغيلي |
|---|---|---|
| الوصول والحزمة المستقلة | ناجح | `/login` و`/statuses` وتفاصيل أصل ديناميكية تعيد HTTP `200` بعد إعادة التشغيل. |
| حالات الأصول | ناجح | إنشاء وقراءة وتعديل حالة بلون Hex عبر API، مع عودة اللون غير الصحيح HTTP `400`. |
| المصادقة والصلاحيات | ناجح | المسار المحمي `/statuses` يعيد HTTP `401` دون رمز و`200` مع رمز المسؤول. |
| الصيانة والجرد | ناجح | اختبارات تكامل وE2E لتدفقات الصيانة والجرد نجحت، إضافة إلى تدفق قبول واجهة تم تنفيذه. |
| العزل بين الجهات وسلامة البيانات | ناجح | اختبارات Tenant Isolation وAuthorization Hardening وIntegrity نجحت. |
| التعريب | ناجح ضمن نطاق التدفقات المختبرة | أُغلقت عيوب الشارات والقواعد والوقت النسبي والتأكيد والصيانة. |

## اختبار الواجهة والتدفقات الرئيسية

اختُبرت شاشة الدخول ولوحة المتابعة وإدارة الأصول والتفاصيل والتبويبات والصيانة والجرد والتقارير والتحليلات والبحث وسجل التدقيق وحالات الأصول. شمل تدفق الصيانة إنشاء أمر ثم بدءه وإكماله، وشمل تدفق الجرد إنشاء دورة وبدءها وتسجيل نتيجة واعتمادها ثم إغلاقها. تمت مراجعة 22 مساراً في لوحة التحكم، وأضاف بناء الإنتاج النهائي المسار `/statuses` إلى الحزمة المستقلة.

| التدفق | النتيجة |
|---|---|
| تسجيل الدخول ثم التنقل إلى لوحة المتابعة | ناجح |
| فتح أصل ومراجعة نظرة عامة ودورة حياة وحركات وصيانة وتدقيق ومرفقات | ناجح |
| إنشاء أمر صيانة ثم بدؤه وإكماله | ناجح |
| إنشاء دورة جرد ثم تسجيل نتيجة واعتمادها وإغلاق الدورة | ناجح |
| عرض التقارير وتنزيل CSV والبحث وسجل التدقيق | ناجح |
| إنشاء حالة أصل وتعديل اسمها ولونها من صفحة البيانات الأساسية | ناجح |

## تحقق API وقاعدة البيانات

أُعيد تشغيل Backend من ناتج البناء واستخدم مخزناً محلياً معزولاً. أكد اختبار CRUD الحي أن حالة الأصل تُحفظ وتُقرأ ثم تُحدّث عبر طبقات Controller وService وRepository، كما تحققت مصفوفة العقد المباشرة من نقاط الصحة والمصادقة والبيانات الأساسية والصيانة والجرد والأصول والتدقيق.

| الفحص المباشر | النتيجة المتوقعة | النتيجة الفعلية |
|---|---:|---:|
| `GET /health` | 200 | 200 |
| `GET /statuses` بلا مصادقة | 401 | 401 |
| `GET /statuses` برمز مسؤول | 200 | 200 |
| `POST /statuses` بلون غير صالح | 400 | 400 |
| `GET /maintenance` برمز مسؤول | 200 | 200 |
| `GET /inventory/cycles` برمز مسؤول | 200 | 200 |
| `GET /assets` برمز مسؤول | 200 | 200 |
| `GET /audit/events` برمز مسؤول | 200 | 200 |

> عالجت عملية التحقق عيباً تشغيلياً كان يجعل `COLOR_INVALID` يعيد `500`. لم تكن الخدمة العاملة قد أُعيد تجميعها بعد تعديل خريطة أخطاء المجال. بعد إعادة بناء Backend وتشغيل النسخة المجمعة عاد العقد الصحيح `400 / VALIDATION_ERROR`.

## نتائج الاختبارات الآلية

بسبب سعة الذاكرة، نُفذت اختبارات Backend في دفعات متتابعة مستقلة بدلاً من عملية Jest واحدة طويلة. انتهت الدفعات الـ45 بنجاح، وشملت الأصول والبيانات الأساسية ودورة الحياة والحركات والجرد والصيانة والتدقيق والمصادقة والصلاحيات والتقارير والتحليلات والتصدير والبحث والإشعارات والتحديثات الفورية. حزمة الواجهة اكتملت من دون فشل.

| الحزمة | النتيجة |
|---|---|
| اختبارات Backend الأساسية والبيانات الأساسية | 8 مجموعات، 40 اختباراً ناجحاً |
| دورة الحياة والحركات والجرد والصيانة | 8 مجموعات، 66 اختباراً ناجحاً |
| المصادقة والصلاحيات والتدقيق وسلامة البيانات | جميع المجموعات نجحت عبر دفعات، بما فيها UUID وIntegrity (34 اختباراً في الدفعة الأخيرة) |
| التحليلات والتقارير وقواعد الأعمال وسير العمل | 8 مجموعات، 58 اختباراً ناجحاً |
| التصدير والبحث والبحث المحفوظ | 7 مجموعات، 41 اختباراً ناجحاً |
| الإشعارات والتقارير المجدولة والتحديثات الفورية | 4 مجموعات، 14 اختباراً ناجحاً |
| واجهة الويب Vitest | 8 ملفات، 54 اختباراً ناجحاً |
| بناء واجهة الإنتاج | ناجح؛ 23 مساراً تم توليدها باستخدام Webpack |

## ملاحظات جاهزية النشر

نسخة الكود اجتازت تحقق الإصدار المحلي وهي جاهزة للانتقال إلى بيئة نشر مراقبة. لا يُعامل PGlite المحلي كقاعدة إنتاج؛ يلزم توفير PostgreSQL مُدار وإعداد `DATABASE_URL` و`JWT_ACCESS_SECRET` و`JWT_REFRESH_SECRET` بقيم إنتاجية سرية قبل النشر العام. كما ينبغي تنفيذ فحص CI بعد دفع الالتزام الأخير إلى المستودع المستقل، ثم إجراء اختبار دخان في بيئة النشر الفعلية.
