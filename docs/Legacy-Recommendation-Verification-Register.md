# سجل تحقق توصيات النظام القديم — الدفعة الأولى

**الغرض:** تأكيد ما نُفذ فعلياً من توصيات النظام السابق، وما بقي مؤجلاً عمداً أو يحتاج تحققاً مستقلاً. لا يُعد بند «منفذ» مكتملًا إلا إذا كان مرتبطاً بعقد API أو واجهة أو اختبار موثق.

## ملخص التدقيق

اكتملت الدفعة الأولى ذات الأولوية التي تمس إدارة الأصول والموظفين وحماية الحذف. لم تُنفذ بقية الميزات دفعة واحدة؛ وهي مؤجلة حسب القيمة والمخاطر حتى لا تضيف واجهات غير محمية أو إجراءات تشغيلية خطرة. أُجريت اختبارات وحدة وواجهة وبناء إنتاج وتحقق API حي لهذه الدفعة.

| الحالة | العدد | المعنى |
|---|---:|---|
| منفذ ومتحقق منه | 11 | توجد واجهة أو API وسجل تحقق واضح. |
| منفذ جزئياً | 3 | توجد قاعدة أو واجهة أساسية، لكن يلزم توسيع منضبط لاحقاً. |
| مؤجل عمداً | 6 | لا يضيف بأمان قبل توفر حماية أو بنية تشغيلية أو بيانات حقيقية. |
| مستبعد من النقل | 4 | سلوك تقني قديم لا يلائم منصة SaaS الحديثة. |

## مصفوفة التحقق التفصيلية

| التوصية المستخرجة من النظام القديم | حالة AssetX الفعلية | دليل التنفيذ أو سبب القرار | الخطوة التالية |
|---|---|---|---|
| إنشاء الأصل والتحقق من الحقول وتوليد الأكواد | منفذ ومتحقق منه | نموذج إنشاء وBackend يولدان الكودين الأساسي والكامل، واختبار وحدة يؤكد نمط الكود. | استمرار مراقبة جودة البيانات. |
| الحفظ والتعديل الواضح للأصل | منفذ ومتحقق منه | زر تعديل ظاهر في قائمة الأصول، نموذج تعديل، وصلاحية `asset.update`. | اختبار تجربة الهاتف عند إعادة تصميم الواجهة. |
| النسخ من أصل | منفذ ومتحقق منه | وضع نسخ يعيد الكمية إلى 1 ويمسح الرقم التسلسلي والباركود، ويولد الأصل الجديد من الخادم. | إضافة كشف تشابه موجّه لاحقاً. |
| التراجع عن تعديل غير محفوظ | منفذ جزئياً | زر يعيد النموذج إلى لقطة الأصل المفتوح. | إضافة تحذير مغادرة عند وجود نموذج متسخ ضمن تحسين تجربة الواجهة. |
| كشف التكرار وقرار دمج/متغير/جديد | منفذ جزئياً | توجد حماية وتحقق أساسيان، لكن لا توجد بعد واجهة قرار الدمج الثلاثي. | لا تنفذ دمجاً تلقائياً؛ صمم توصية بشرية قابلة للتفسير فقط. |
| الحذف الناعم للأصل | منفذ ومتحقق منه | `DELETE /assets/:id` يعطل السجل، ويتطلب `asset.delete`، ويعيد الأصل المحذوف `404`. | الاحتفاظ بسياسة عدم الحذف المادي. |
| حماية الأصل المرتبط | منفذ ومتحقق منه | فحص الحركات والجرد والصيانة ودورات الجرد المفتوحة، مع اختبار أصل مرتبط بحركة. | يمكن لاحقاً عرض ملخص الارتباطات في رسالة الرفض. |
| تجاوز إداري لحذف أصل مرتبط | مؤجل عمداً | السماح بالتجاوز يضعف الأثر التاريخي إذا غاب نموذج موافقات موجه. | يدرس فقط مع Maker–Checker للحالات الحساسة. |
| تعديل جماعي للأصول | منفذ ومتحقق منه | تعديل الموقع والعهدة والحالة والملاحظات، بنتيجة لكل أصل وحماية ارتباطات. | لا توسع للكمية أو سنة الجرد قبل قواعد أعمال موثقة. |
| أنواع الأصول الرئيسية والفرعية | منفذ ومتحقق منه | إنشاء وإضافة فرعية وإعادة تسمية، وتعطيل ناعم محمي من الأنواع الفرعية والأصول المرتبطة، مع صلاحية وتدقيق. | تحسين رسالة رفض الارتباطات بعد إقرار صياغتها. |
| حالات الأصول | منفذ ومتحقق منه | إنشاء وتعديل ولون الحالة، وتعطيل ناعم محمي من الأصول المرتبطة، مع صلاحية وتدقيق. | تحسين رسالة رفض الارتباطات بعد إقرار صياغتها. |
| الموظفون | منفذ ومتحقق منه | إضافة وتعديل وتعطيل ناعم عبر واجهة عربية، وحماية خلفية عند وجود أصول نشطة. | إضافة بحث وحقول تنظيمية فقط عند حاجة تشغيلية. |
| نقل الأصل وسجل الحركات | منفذ جزئياً | تدفق النقل والاعتماد والتدقيق موجود؛ لم يُعاد اختبار كل فلاتر التاريخ في هذه الدفعة. | إجراء تحقق قبول مستقل عند تحديث وحدة الحركات. |
| دورة الجرد وسجلها والمراجعة | منفذ جزئياً | إنشاء لقطة وبدء وجرد واعتماد وإغلاق موجودة ومتحقق منها سابقاً. | إضافة الطباعة الموقعة ولوحة مراجعة موسعة في حزمة تقارير. |
| التقارير والطباعة العربية ونموذج الجرد | منفذ جزئياً | تصدير مدقق وتقارير أساسية موجودة. | منشئ تقرير منضبط ثم PDF جرد موقعّع؛ لا طباعة متصفح خام. |
| الاستيراد بأوضاع تخطي/تحديث/استبدال | مؤجل عمداً | لا يوجد استيراد كامل؛ الاستبدال غير آمن من دون Dry Run وتسوية ونسخة قابلة للاستعادة. | يبدأ بإطار ترحيل محكوم عندما تعتمد بيانات المصدر. |
| النسخ الاحتياطي والاستعادة | مؤجل عمداً | لا ينقل SQL Server Backup/Restore للواجهة. | سياسة PostgreSQL مدارة، احتفاظ واختبار استعادة قبل النشر. |
| إدارة المستخدمين ومصفوفة الصلاحيات | منفذ جزئياً | RBAC وحراسة API موجودان؛ لا توجد واجهة إدارة متقدمة بعد. | حزمة مستقلة عالية الحساسية بعد تثبيت نموذج الأدوار. |
| SHA-256 وإجراءات SQL Server وWPF | مستبعد من النقل | لا تلائم أمان وهوية وبيئة AssetX الحديثة. | لا إجراء. |

## أدلة الاختبار المتاحة

| التحقق | النتيجة المسجلة |
|---|---|
| Backend TypeScript | ناجح بعد إضافة الحذف الناعم والتعديل الجماعي. |
| وحدة الأصول | 11 اختباراً ناجحاً، بما فيها حماية الأصل المرتبط وحذف ناعم وتعديل جماعي. |
| واجهة الويب | 54 اختباراً ناجحاً في 8 ملفات. |
| بناء Webpack | ناجح مع توليد 23 مساراً. |
| اختبار API حي | إنشاء أصل، تعديل جماعي، حذف ناعم، ثم تحقق `404` بعد الحذف. |
| وحدة البيانات الأساسية | 5 اختبارات ناجحة لتعطيل النوع/الحالة، وحظر النوع الذي له أطفال أو أصول، وحظر الحالة المرتبطة بأصول. |
| API حي للتعطيل | أنشئ موقع وفئة وحالة وأصل مرتبط بها؛ أعاد `DELETE /categories/:id` و`DELETE /statuses/:id` الرمز `409` مع `CATEGORY_HAS_ASSETS` و`STATUS_HAS_ASSETS`. |

## القرار التسلسلي للدفعات القادمة

اكتملت **حماية البيانات الأساسية** لأنواع الأصول وحالاتها بعقود تعطيل محمية بدلاً من الحذف المادي. ينتقل العمل إلى تحسين الرسائل العربية التفصيلية، وتحديث صفحات الأصول والموظفين والجرد بالنمط المؤسسي، ثم الاستيراد المحكوم والإعدادات وسياسة النسخ الاحتياطي.
