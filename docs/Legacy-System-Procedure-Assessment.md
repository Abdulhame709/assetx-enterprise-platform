# تقييم إجراءات النظام السابق ومقابلها في AssetX

**المصدر:** ملفات C# المرفقة من النظام السابق.  
**الغرض:** استخراج السلوك وقواعد الأعمال القابلة للاحتفاظ، ثم تنفيذ مكافئ حديث في Next.js وNestJS؛ لا يُعاد استخدام WPF أو SQL Server أو منطق الواجهة القديم حرفياً.

## الخلاصة التنفيذية

النظام السابق يحتوي على قواعد مؤسسية مفيدة يجب الحفاظ عليها: **النسخ من أصل قائم، الحذف الناعم، حماية الأصول المرتبطة، مصفوفة صلاحيات خماسية، تدقيق للعمليات، وتصدير/طباعة عربية قابلة للتتبع**. المنصة الحالية تتضمن أساساً جيداً في المصادقة والصلاحيات الدقيقة والتدقيق والتصدير، لكنها لا تعرض أو لا تنفذ بعد بعض الإجراءات في واجهات الأصول والموظفين والأصناف، ولا تفرض بعد سياسة حماية الأصل المرتبط في Backend عند التعديل والحذف.

> المبدأ المعتمد: **كل زر ظاهر يجب أن يكون وراء صلاحية في الواجهة، ومُنفذاً ومُدققاً في API؛ ولا يكفي إخفاء الزر وحده كحماية.**

## الإجراءات المستخرجة من ملفات الأصول

| الإجراء أو القاعدة | السلوك في النظام السابق | المقابل المطلوب في AssetX الحديثة | الأولوية |
|---|---|---|---|
| إنشاء أصل | يطلب الاسم والنوع والموقع والحالة والكمية الموجبة، ويولد كوداً أساسياً وكاملاً | موجود جزئياً؛ يستمر التحقق في API وتبقى الأكواد مولدة في الخادم | مكتمل جزئياً |
| حفظ وتعديل | يحفظ التغييرات بعد التحقق ويعرض بيانات العرض المرتبطة | نموذج الحفظ موجود؛ يلزم إظهار إجراء التعديل بصورة أوضح في قائمة وتفاصيل الأصل | عالية |
| نسخ من أصل | ينسخ البيانات التجارية والمراجع والمالية، لكنه يعيد الكمية إلى 1 ويمسح الباركود والرقم التسلسلي والأكواد النظامية | زر **«نسخ من أصل»** يفتح نموذج إنشاء ممتلئاً بالحقول المسموح نسخها فقط؛ ينشئ الخادم الأكواد الجديدة | عالية |
| تراجع/إلغاء | يعيد النموذج إلى حالة محفوظة أو جديدة ولا يحفظ تغيرات غير مؤكدة | زر **«إلغاء التغييرات»** في نموذج الأصل، وتحذير قبل إغلاق نموذج متسخ؛ لا يعيد حذف سجل تم حفظه | عالية |
| كشف التطابق | مقارنة اسم/نوع/نوع فرعي/موقع/حالة/موديل/عهدة، مع فصل حالة الاسم المتشابه | الاستمرار في كشف التشابه الموجود وإظهاره عند الإنشاء والنسخ | متوسطة |
| حذف أصل | الحذف المنطقي عبر `IsActive` مع اشتراطات حماية | نقطة حذف ناعم مؤكدة وصلاحية `asset.delete` وسجل تدقيق؛ لا حذف مادي | حرجة |
| تعديل جماعي | تحديث مجموعة أصول عبر حقول مشتركة | لوحة تعديل جماعي محددة الحقول مع معاينة العدد وتأثيرات الحقول وسجل تدقيق لكل أصل | عالية |

## حماية الأصول المرتبطة

ملف `AssetProtectionHelper.cs` يفحص أربع فئات قبل التعديل أو الحذف: **الحركات، سجلات الجرد، سجلات الصيانة، ودورات الجرد النشطة**. الأصل غير المرتبط قابل للتعديل أو الحذف وفق الصلاحية؛ الأصل المرتبط يحتاج تجاوزاً إدارياً صريحاً مع تحذير يشرح الارتباطات.

| القرار | السلوك الحديث المقترح |
|---|---|
| أصل غير مرتبط | يسمح Backend بالتعديل أو الحذف الناعم عند امتلاك الصلاحية المناسبة. |
| أصل مرتبط ومستخدم عادي | يعيد Backend استجابة منع منظمة مع ملخص الارتباطات؛ تعرض الواجهة رسالة عربية واضحة. |
| أصل مرتبط ومدير نظام | لا يكون السماح تلقائياً: تعرض الواجهة ملخص الارتباطات وتتطلب تأكيداً صريحاً؛ يرسل الطلب خيار تجاوز إداري تدققه API. |
| حذف جماعي | لا ينفذ جزئياً بصمت؛ يعيد نتيجة لكل أصل ويبين المحمي أو الفاشل، مع عدم إزالة السجلات فعلياً. |

## الصلاحيات والتدقيق

يعرّف النظام السابق لكل وحدة خمسة أفعال: **عرض، إضافة، تعديل، حذف، طباعة/تصدير**، مع تجاوز مدير النظام. المنصة الحديثة تستخدم مفاتيح صلاحيات دقيقة وحارس API؛ لذا تعتمد المقابلة التالية:

| الإجراء القديم | المقابل الحديث |
|---|---|
| View | `*.view` مع حارس API والتنقل المقيد |
| Add | `*.create` لإظهار «جديد» وتنفيذ POST |
| Edit / Save | `*.update` لإظهار «تعديل» و«حفظ» وتنفيذ PATCH |
| Delete | `*.delete` لإظهار «حذف» وتنفيذ الحذف الناعم |
| Print | `export.*` أو صلاحية طباعة مستقلة عند إضافة معاينات الطباعة |

يلزم أن تسجل كل عملية: المستخدم، الجهة، الكيان، المعرّف، نوع الإجراء، الحقول أو القيم المعدلة، الزمن، ونتيجة العملية. يحتوي النظام الحديث على أساس تدقيق مناسب؛ تضاف أحداث للنسخ، التعديل الجماعي، الحذف الناعم، ورفض الحماية أو تجاوزها.

## مصفوفة المطابقة مع النسخة الحالية

| المجال | الموجود حالياً في AssetX | الفجوة المؤكدة | قرار التصحيح |
|---|---|---|---|
| قائمة الأصول | إنشاء، تصدير، فلترة، اختيار متعدد، وطلب استغناء | لا توجد إجراءات واضحة للتعديل الجماعي أو النسخ أو الحذف الناعم | إضافة شريط إجراءات جماعية متجاوب ولوحة تعديل جماعي ونقطة API مقيدة بالصلاحية. |
| نموذج الأصل | إنشاء وتعديل وحفظ وتحقق حقول أساسي | لا يوجد «نسخ من أصل»، ولا تتبع للتغييرات غير المحفوظة، ولا إعادة ضبط صريحة | دعم وضع `copy` مع قواعد النسخ المستخرجة، و`isDirty` وزر إلغاء تغييرات آمن. |
| Backend للأصول | إنشاء، بحث، تعديل فردي، نقل وتغيير حالة | لا توجد حالياً مسارات حذف ناعم أو تعديل جماعي، ولا سياسة حماية الارتباطات | إضافة `DELETE /assets/:id` و`PATCH /assets/bulk`، وتنفيذ حماية الخادم قبل أي تعديل/حذف. |
| بيانات الأصناف | إنشاء صنف رئيسي أو فرعي وإعادة تسمية | أزرار الإجراءات تعتمد المرور بالماوس، ولا توجد سياسة نسخ أو حذف | إظهار إجراءات اللمس بوضوح، وإضافة نسخة كإنشاء جديد؛ لا يضاف حذف قبل مراجعة منطق ارتباط الصنف بالأصول. |
| الموظفون | Backend يدعم CRUD وحذفاً ناعماً | الواجهة الحالية عرض فقط ولا تحتوي أزرار الإدارة | بناء نموذج موظف وربط الإضافة والتعديل والحذف الناعم مع تأكيد وصلاحيات. |
| المواقع | CRUD ومودال وتأكيد حذف موجودة | لا توجد فجوة حرجة؛ تحسين ظهور أزرار اللمس فقط | إعادة استخدام نمط أزرار شجرة المواقع في الأصناف وبقية البيانات الأساسية. |
| حالات الأصول | إنشاء وتعديل وحفظ | التعديل يظهر عند المرور ولا يوجد حذف في عقد API | تحسين الظهور في اللمس، والإبقاء على عدم عرض حذف حتى تتوفر حماية مرجعية في Backend. |
| الصلاحيات | مفاتيح دقيقة وحارس Backend يدقق منح/رفض الصلاحيات | مفتاح `employee.delete` مفقود من واجهة الويب رغم وجوده في Backend | إضافة المفتاح واستخدام `PermissionGate` على جميع أفعال CRUD. |
| تقارير وتصدير | بنية تصدير مدققة موجودة وبعض التصدير من الواجهة | لا توجد معاينة طباعة أو نموذج جرد فارغ بتوقيعات | إضافة هذه كميزة تقارير مستقلة بعد تسلم قالب شاشة الجرد أو SQL القديم. |
| نسخ احتياطي | سياسة النشر تطلب PostgreSQL مُداراً | لا توجد واجهة إعداد تشغيلية أو سجل سياسة الاحتفاظ في التطبيق | التعامل معها كتجهيز بنية تشغيلية، لا كزر نسخ SQL محلي. |

## التقارير والتصدير والطباعة

توفر ملفات التقارير السابقة تصدير Excel وCSV بالعربية وRTL، والعنوان والفلاتر واسم المصدر والتاريخ وعدد السجلات، مع تلوين نتيجة الجرد. كما توفر طباعة تقرير ونموذج جرد فارغ مجمع حسب الموقع، وخانات النتائج الفعلية وتوقيعات المستلم وأعضاء اللجنة ورئيسها، وتذييل يحوي من طبع التقرير والصفحات والوقت.

المقابل الحديث لا يعيد توليد WPF؛ بل يستخدم خدمات التصدير الحالية لإنتاج CSV/XLSX/PDF مع البيانات الوصفية نفسها. تتطلب طباعة نموذج الجرد الفارغ صفحة أو PDF مُنشأ على الخادم، مع صلاحيات ومعلومات دورة الجرد وتوقيعات اللجنة، وهي ميزة مستقلة عن تصدير قائمة الأصول العادية.

## النسخ الاحتياطي والتشغيل

يوضح النظام السابق إعدادات تمكين النسخ والجدولة والاحتفاظ وآخر تنفيذ وسجل التدقيق، إضافة إلى الاستعادة المسيطر عليها. لا ينقل AssetX أوامر SQL Server أو مسارات الأقراص المحلية. بدلاً من ذلك، يحافظ على السلوك المؤسسي في بيئة PostgreSQL مُدارة: **نسخ مجدول من المزود، احتفاظ محدد، تشفير، اختبار استعادة، سجل تدقيق، وخطة اعتماد قبل تنفيذ استعادة**.

## ما لا ينقل كما هو

| العنصر القديم | القرار |
|---|---|
| SHA-256 المباشر لكلمات المرور | لا ينقل؛ تبقى سياسة التشفير الحديثة في المنصة واستخدام تجزئة كلمات مرور قوية. |
| WPF و`MessageBox` و`PrintDialog` | لا ينقل؛ تستبدل بنماذج ومربعات تأكيد وPDF/طباعة متصفح متجاوبة. |
| SQL Server `BACKUP` و`RESTORE WITH REPLACE` ومسار محلي | لا ينقل؛ تستبدل بسياسة نسخ واستعادة PostgreSQL مُدارة. |
| `IDENTITY_INSERT` و`SCOPE_IDENTITY` | لا ينقل؛ المنصة تعتمد UUID ومعاملات ومستودعات Clean Architecture. |

## ملفات إضافية مطلوبة لإكمال المطابقة الدقيقة

لإعادة إنتاج تفاصيل تجربة المستخدم وقواعد التعديل الجماعي بلا افتراضات، يلزم إرفاق الملفات التالية من النظام السابق إن كانت متاحة:

1. شاشة أو ViewModel إدارة الأصول التي تحتوي أوامر **جديد/حفظ/تعديل/نسخ/تراجع/حذف** واختصارات لوحة المفاتيح.
2. شاشة أو خدمة **التعديل الجماعي**، مع الحقول التي تسمح بتعديلها ومنطق التأكيد والنتائج الجزئية.
3. الخدمات أو الإجراءات المخزنة الخاصة بإنشاء الأصل وتعديله وحذفه وكشف التكرار.
4. ملفات شاشات **أنواع الأصول، الموظفين، المواقع، حالات الأصول والموديلات** لمعرفة قواعد الحذف والترابط لكل بيانات أساسية.
5. مخطط الجداول أو ملفات SQL لجداول الأصول والحركات والجرد والصيانة والصلاحيات وسجل التدقيق.
6. شاشة إعدادات النسخ الاحتياطي أو سياسة اعتماد الاستعادة إن كان فيها سير موافقة خاص.

## إجراءات تفصيلية مؤكدة من الحزمة الموسعة

### شاشة الأصول

تعرض شاشة الأصول القديمة أزراراً صريحة: **جديد، حفظ، نسخ، حذف، تراجع، تعديل جماعي، متشابهات، أكواد محذوفة، وطباعة**. يمثل التراجع إعادة تحميل السجل المحفوظ أو إعادة ضبط سجل جديد؛ ولا يمثل استعادة حذف محفوظ. عند وجود تغييرات غير محفوظة، يظهر قرار بثلاثة خيارات: حفظ قبل المغادرة، تجاهل التغييرات، أو البقاء في النموذج. تستخدم الاختصارات `Ctrl+S` للحفظ و`Ctrl+N` أو `F3` للجديد و`F4` للنسخ و`F5` للتحديث و`Esc` للتراجع و`Ctrl+P` للطباعة.

ينشئ إجراء النسخ نموذج أصل جديد مملوءاً بالبيانات التجارية، ويضبط الكمية إلى 1، ويحذف الرقم التسلسلي والباركود، ويعيد إنشاء الكود الكامل في الخادم. عند حفظ أصل جديد، يمر من قرار تكرار ثلاثي: **دمج** إذا تطابقت حقول الهوية الأساسية، أو **متغير جديد** إذا تطابق الاسم واختلفت سياقات الهوية، أو **أصل جديد**. يجب أن يعرض التطبيق الحديث هذا القرار ولا يدمج الكميات تلقائياً.

### التعديل الجماعي للأصول

يختار النظام القديم مجموعة الأصول وفق أحد المرشحات: الكود الأساسي أو الاسم أو الموقع أو الحالة أو النوع. ثم يغير حقلاً واحداً ضمن: الموقع، الحالة، الموظف المسؤول، الكمية، أو سنة الجرد، ويعرض عدد الأصول والحقل والقيمة الجديدة قبل التأكيد. في AssetX يُستبدل مربع الإدخال بقائمة اختيار واضحة وسجل معاينة، وتنفذ العملية في API داخل معاملة وتعيد نتيجة لكل أصل. لا يسمح التعديل الجماعي بتجاوز حماية أصل مرتبط من دون تأكيد إداري صريح.

### أنواع الأصول والموظفون

تدعم أنواع الأصول الرئيسية والفرعية الإضافة والتعديل والإلغاء والحذف مع شجرة هرمية ومسار كامل ومستوى. يمنع حذف النوع الرئيسي عند وجود أنواع فرعية أو أصول مرتبطة؛ ويمنع حذف النوع الفرعي عند وجود أطفال أو أصول مرتبطة به. لا يوجد في المصدر القديم إجراء نسخ أو تعديل جماعي للأنواع، لذلك لا يكون أي منهما إلزامياً.

تدعم شاشة الموظفين الجديدة والتعديل والحفظ والإلغاء والحذف. يمنع الحذف عند ارتباط الموظف بأصل ويقترح التعطيل بدلاً منه. في المنصة الحديثة يبقى الحذف ناعماً ويستخدم `employee.delete`، ولا يعاد استخدام كود موظف محذوف لأنه ليس قاعدة مطلوبة في نموذج UUID الحديث.

### نقل الأصل وسجل الحركات

تحدد شاشة النقل الأصل وتعرض قيم «من» ثم تملأ «إلى» بالقيم الحالية. يطلب النقل اختيار نوع الحركة؛ النقل العادي يحتاج موقعاً جديداً، بينما الإتلاف أو الاستغناء يعطل الأصل ويختار حالة مناسبة ولا يطلب موقعاً أو موظفاً جديداً. تسجل العملية المواقع والعهدة والحالة قبل وبعد والسبب والمرجع والمعتمد والملاحظات. تاريخ الحركات يوفر بحثاً وفلترة وعرض تفاصيل وتصدير Excel وطباعة.

### الجرد

يحسب تحديث سجل الجرد النتيجة بهذا الترتيب: كمية صفر = مفقود، أقل من المتوقعة = عجز، أكبر = زيادة، موقع مختلف مع كمية مساوية = منقول، وإلا = مطابق. تنسخ المطابقة السريعة لسجل واحد أو لموقع كامل جميع القيم المتوقعة إلى القيم الفعلية وتقتصر العملية الجماعية على السجلات غير المجردة. يعيد «إلغاء الجرد» السجل إلى «لم يُجرد»، ويمسح القيم الفعلية والتاريخ والمجرد والملاحظات وحالة التحقق. توفر المراجعة تحققاً وإلغاء تحقق وتحقق الكل، إضافة إلى تصدير وطباعة ونموذج جرد فارغ مجمع حسب الموقع.

### دورات الجرد والمراجعة

تمنع دورة الجرد القديمة تكرار السنة وتمنع الإنشاء عندما لا توجد أصول نشطة. عند الإنشاء تأخذ لقطة من الأصول النشطة، تشمل الموقع والحالة والكمية والعهدة المتوقعة، ثم تبقى النتائج ضمن السجل بدلاً من تعديل الأصل مباشرة. يمكن تعديل اسم الدورة وتواريخها وملاحظاتها، ويُسجل تاريخ الإغلاق عند الإغلاق. لا يحذف النظام دورة مغلقة؛ ويزيل أعضاء الفريق والسجلات قبل حذف دورة غير مغلقة.

في مرحلة المراجعة لا يُتحقق من سجل «لم يُجرد». يدعم النظام التحقق الفردي، إلغاء التحقق، إلغاء الجرد، والتحقق الجماعي للسجلات المجردة غير المعتمدة فقط. هذا يطابق المبدأ الحالي في AssetX بأن اعتماد الجرد لا يغير الأصل تلقائياً من دون مراجعة بشرية.

### التقارير

تتيح تقارير الأصول القديمة اختيار الفلاتر بحسب الاسم، الموقع الرئيسي والفرعي الهرمي، النوع الفرعي، الحالة، الموظف، الموديل، نطاق السعر، تاريخ الشراء، سنة الجرد، والباركود أو الرقم التسلسلي. تدعم التقرير التفصيلي والتجميع حسب حقول محددة، مع إظهار عدد السجلات والكمية والقيمة وعدد المواقع والأنواع، ووصف الفلاتر في الإخراج. يجب أن تستخدم التقارير الحديثة التصدير المدقق الموجود في Backend، مع إضافة واجهة بناء تقرير واضحة قبل إضافة أي قالب طباعة.

### الاستيراد

يعرض المصدر القديم ثلاثة أوضاع مفيدة: **إضافة الجديد وتخطي الموجود**، و**تحديث الموجود وإضافة الجديد**، و**استبدال البيانات بعد تحذير صريح غير قابل للتراجع**. يتحقق الاستيراد من التبعيات ثم ينفذ بالترتيب: الحالات، الأنواع، الأنواع الفرعية، المواقع الرئيسية والفرعية، الموديلات، الموظفون، ثم الأصول. يعرض ملخصاً بعدد المستورد والمحدّث والمتخطى، ويحفظ تفاصيل الأخطاء ويوفر تصديراً للتقرير. في AssetX ينبغي تنفيذ الاستيراد كمهمة خلفية/معاملة مدققة مع معاينة ومطابقة أعمدة، ولا يُتاح وضع الاستبدال على الإنتاج إلا خلف صلاحية تشغيلية مرتفعة وخطة نسخ احتياطي معتمدة.

### النسخ الاحتياطي والإعدادات

تتضمن الواجهة السابقة زر إنشاء نسخة مع سجل التنفيذ وحجم الناتج، كما تتطلب قبل الاستعادة نسخة تلقائية من الحالة الحالية ثم تأكيداً نهائياً. توفر الإعدادات تمكين النسخ التلقائي والجدولة وعدد النسخ المحتفظ بها وآخر تنفيذ، إضافة إلى اسم المنظمة وشعارها وعنوان التقرير وتذييله وطريقة الإهلاك وبداية السنة المالية. في المنصة الحديثة تصبح هذه العناصر **سياسات تشغيل وإعدادات مؤسسة**: النسخ والاستعادة عبر موفر PostgreSQL المدارة مع سجل مدقق واختبار استعادة، وتبقى إعدادات الهوية والتقارير والإهلاك واجهة إدارة مقيدة بالصلاحية.

### التدقيق والمستخدمون والصلاحيات

يوفر سجل التدقيق القديم فلاتر بالتاريخ ونوع الإجراء والمستخدم والنص، ويعرض المستخدم والكيان والسجل والقيم قبل وبعد ومحطة العمل. أما إدارة المستخدمين فتدعم الإضافة والتعديل والتعطيل بدلاً من الحذف النهائي، وتمنع المستخدم من تعطيل حسابه الحالي، وتنشئ صف صلاحيات افتراضي لكل وحدة، ثم تتيح نافذة مستقلة لحفظ أفعال العرض والإضافة والتعديل والحذف والطباعة. توجد في AssetX الحديثة حراسة API وتدقيق للصلاحيات؛ المطلوب هو إظهار هذه الإجراءات بوضوح وتوسيع أحداث التدقيق الجديدة، لا العودة إلى أدوار نصية أو SHA-256 القديم.

|---|---|---|---|
| الأصول | قائمة قابلة للاختيار مع إضافة وتصدير واستغناء؛ API للتعديل الفردي والنقل والحالة | لا توجد API أو أزرار للحذف الناعم والتعديل الجماعي والنسخ والتراجع | تنفيذ حزمة إجراءات الأصول أولاً، في Backend ثم الواجهة، وفق قواعد الحماية والتدقيق أعلاه. |
| أنواع الأصول | إنشاء رئيسي/فرعي وإعادة تسمية، لكن الأيقونات مخفية عند المرور | اكتشاف ضعيف للمس، ولا يوجد حذف في API | جعل الأفعال ظاهرة على اللمس؛ إضافة حذف محمي فقط بعد بناء فحص ارتباط الأنواع والأصول. النسخ ليس مطلباً قديماً إلزامياً. |

| المستخدمون والصلاحيات | API المستخدم الحالي وتحديث الملف الشخصي فقط؛ صفحة الإدارة تعرض معلومات الجلسة | لا توجد إدارة مستخدمين أو تعيين صلاحيات في الواجهة | مرحلة مستقلة عالية الحساسية بعد تثبيت نموذج أدوار وصلاحيات المنظمة الحالي. |
| الاستيراد | صفحة تنزيل قالب CSV فقط | لا يوجد رفع أو معاينة أو أوضاع تخطي/تحديث أو سجل أخطاء | بناء استيراد أصول على دفعة لاحقة؛ يبدأ بالمعاينة والتخطي والتحديث، ويؤجل الاستبدال إلى ضوابط تشغيلية. |

| التقارير | تصدير مدقق موجود وصفحة تقارير أولية | لا منشئ تقارير وفلاتر هرمية ولا طباعة PDF للتوقيعات | مرحلة تقارير لاحقة: منشئ فلاتر وتصدير، ثم نموذج جرد PDF/طباعة. |
| الحركات والجرد | صفحات وAPI مكتملة وظيفياً إلى حد كبير | يلزم فقط مراجعة عرض معلومات السبب/المرجع/المعتمد وتفاصيل الاعتماد | تحسينات لاحقة لا تمنع حزمة أزرار الأصول والبيانات الأساسية. |

## أولوية التنفيذ المعتمدة

1. **حزمة إجراءات الأصول والموظفين**: إظهار الأزرار، النسخ، الإلغاء الآمن، الحذف الناعم المحمي، والتعديل الجماعي؛ فهي الاستجابة المباشرة لملاحظة المستخدم.
2. **حماية البيانات الأساسية**: جعل أفعال الأصناف والحالات والمواقع قابلة للاكتشاف على اللمس، وإضافة حذف محمي عند توفر عقود Backend.
3. **التقارير والاستيراد والإعدادات**: تنفذ كحزم مستقلة مع صلاحيات وتدقيق، ولا تخلط مع حزمة الإجراءات الأساسية.
