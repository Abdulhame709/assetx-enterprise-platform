# قرار الدفعة التالية — حماية البيانات الأساسية وتجربة الواجهة

**القرار:** تبدأ الدفعة التالية بإكمال إجراءات البيانات الأساسية الآمنة، بالتوازي مع توحيد أسلوب واجهة مؤسسي. لا تبدأ حزمة الاستيراد أو النسخ الاحتياطي أو محرك الموافقات في هذه الدفعة، لأنها تحتاج عمليات تشغيل وبيانات واقعية وضوابط أوسع.

## النطاق المعتمد

| العنصر | القرار | سبب الاختيار |
|---|---|---|
| تعطيل نوع الأصل المحمي | يعتمد | يكمل فجوة CRUD دون حذف مادي؛ لا يسمح عند وجود نوع فرعي أو أصل نشط مرتبط. |
| تعطيل حالة الأصل المحمية | يعتمد | يمنع استخدام الحالة مستقبلاً مع حفظ التاريخ؛ لا يسمح عند وجود أصل نشط مرتبط. |
| عرض سبب المنع بالعربية | يعتمد | يحول رسالة الفشل من خطأ تقني إلى قرار مفهوم للمستخدم. |
| سجل تدقيق للتعطيل | يعتمد | يحافظ على قابلية المراجعة ويطابق قواعد النظام السابق. |
| تحديث الواجهة المؤسسي | يعتمد | يرفع وضوح الإجراءات وسهولة الهاتف من دون تغيير منطق العمل أو إضافة تزيين مبالغ فيه. |
| حذف مادي للأصناف أو الحالات | مرفوض | يضر بالبيانات التاريخية وبالمراجع. |
| استيراد استبدالي أو استعادة قاعدة من الواجهة | مؤجل | يحتاج خطة ترحيل ونسخ واستعادة معتمدة خارج واجهة المستخدم العامة. |
| محرك موافقات عام وذكاء تنبئي | مؤجل | لا يحقق أفضل قيمة في المرحلة الحالية ولا تتوفر بيانات تشغيل كافية. |

## قاعدة الاختبار الإلزامية

لا يدمج أي تغيير في هذه الدفعة قبل نجاح: اختبار وحدة لخدمة الأعمال، واختبار عقد API للحالة المسموح بها وحالة الرفض، واختبارات الواجهة، وبناء إنتاج. وتجرى مراجعة مرئية للصفحات المتأثرة بعد اكتمال البناء.
