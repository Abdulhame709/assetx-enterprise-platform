# AssetX Preview QA Report

## نطاق الفحص

تم تشغيل نسخة `assetx-enterprise-platform` محلياً مع backend على المنفذ 3001 وواجهة Next.js standalone على المنفذ 3000، ثم عرضها عبر رابط معاينة مؤقت. شمل الفحص تسجيل الدخول، لوحة التحكم، الأصول، الجرد، الحركات، المواقع، أنواع الأصول، الامتثال، التدقيق، وتبديل اللغة إلى العربية.

> رابط المعاينة المؤقت: `https://3000-i2nf0myomnheik1ssraam-a41e590b.us3.manus.computer/login`

الرابط مخصص للمراجعة أثناء تشغيل البيئة الحالية، وليس رابط نشر دائم أو production.

## النتيجة العامة

الواجهة تمتلك أساساً بصرياً متسقاً ومهنياً نسبياً: sidebar واضح، مجموعات تنقل منطقية، breadcrumbs، بطاقات KPI، أدوات تصفية، حالات فارغة، أزرار إجراءات، وجدول تدقيق غني. شاشة Compliance هي الأكثر نضجاً بصرياً، بينما شاشة Inventory تحتاج إلى empty state أكثر توجيهاً لأنها تمثل أهم تدفق ميداني سيُنقل لاحقاً إلى الموبايل.

## إصلاح منفذ أثناء الفحص

عند تشغيل Next.js standalone لأول مرة، ظهرت صفحة الدخول دون CSS لأن ملفات `.next/static` لم تكن منسوخة إلى مجلد standalone. أُضيف `web/scripts/prepare-standalone.sh` وربط بأمر build، كما تم تعديل أمر start إلى `node .next/standalone/server.js`. بعد إعادة البناء ظهرت الواجهة بالتنسيق الكامل، واختفى تحذير `next start` غير المتوافق مع output standalone.

## الأولويات التصميمية التالية

ينبغي أولاً إضافة empty states موجهة للـ Dashboard وInventory، مع بيانات demo اختيارية في بيئة preview فقط حتى يمكن تقييم الرسوم والجداول بصرياً. ثم ينبغي استكمال قاموس العربية للنصوص الثابتة في shell والصفحات، لا الاكتفاء بعكس الاتجاه والتاريخ. بعد ذلك يجب إجراء فحص narrow/mobile viewport فعلي، ثم مراجعة النماذج المنبثقة والـ loading/error states والرسائل بعد الحفظ والحذف.

لا يُنصح بإعلان التصميم جاهزاً للإنتاج قبل اختبار تدفق حقيقي يتضمن إنشاء أصل، إنشاء دورة جرد، تسجيل حركة، الموافقة عليها، ظهورها في التدقيق، ثم اختبار نفس التدفق على شاشة موبايل ضيقة.
