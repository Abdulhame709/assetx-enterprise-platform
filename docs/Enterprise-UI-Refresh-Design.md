# تصميم تحديث الواجهات المؤسسية — AssetX Web

**الهدف:** رفع جودة العرض إلى نمط منصة مؤسسية موثوقة وكثيفة المعلومات، لا واجهة تسويقية أو زخرفية. يظل التصميم عربيّاً أولاً، متجاوباً، سريع الفهم، ومناسباً للعمل المكتبي والهاتف.

## المبدأ البصري

تستخدم المنصة خلفية عمل محايدة مائلة إلى الرمادي المزرق، مع أسطح بيضاء واضحة، وحد أزرق موثوق للإجراءات الأساسية، وتباين مدروس للحالات التحذيرية. لا تستخدم تدرجات لونية زخرفية أو بطاقات عائمة في كل مكان؛ تظهر الرفعة فقط للمعلومات التي تحتاج تركيزاً، بينما تبقى الجداول والبيانات المرجعية كثيفة وسهلة المسح.

| القرار | التطبيق العملي |
|---|---|
| تسلسل مؤسسي واضح | رأس ثابت خفيف، تنقل جانبي واضح، عنوان صفحة متصل بالمسار، وإجراء أساسي واحد ظاهر. |
| كثافة قابلة للتحكم | الجداول هي وضع العرض الافتراضي؛ البطاقات تستخدم للملخصات والتنبيهات، لا لكل سجل. |
| ثقة بالبيانات | رموز الحالة، آخر تحديث، عدد السجلات، ورسائل الخطأ/النجاح تظهر بصياغة صريحة. |
| العربية أولاً | محاذاة واتجاه RTL، مسافات مناسبة للنص العربي، أزرار لمس لا تقل عن 44px في الهاتف، وأيقونة مع نص عند الإجراء الحساس. |
| وصولية | حلقات تركيز، تباين مناسب، عناوين حقيقية، وغياب الاعتماد على المرور بالماوس لإظهار أي فعل لازم. |

## لغة الألوان والمساحات

| الرمز | الاستخدام |
|---|---|
| `--ax-primary` | الإجراء الأساسي، الرابط المؤكد، التحديد النشط. |
| `--ax-surface-raised` | خلفية مساحة العمل والمناطق الثانوية. |
| `--ax-surface-overlay` | القوائم والمربعات المنبثقة فقط. |
| `--ax-line` | فواصل الجداول والحدود الخفيفة؛ لا تستخدم كإطار ثقيل لكل عنصر. |
| `success / warning / danger` | حالة عملية أو مخاطرة فقط، ولا تستخدم للتزيين. |

تستخدم الصفحة شبكة مسافات 4/8/12/16/24/32 بكسل. وتكون حواف اللوحات 12 بكسل في السياق العادي و16 بكسل للمساحات الملخصة فقط. يحافظ المحتوى على حد قراءة مريح في الشاشات الكبيرة بدل تمديد النماذج إلى كامل العرض.

## الغلاف المؤسسي

1. **الشريط الجانبي:** هوية Product واضحة، أقسام مترابطة، رابط نشط بحد/شريط جانبي وليس مجرد لون خلفية، ومنطقة سفلية صغيرة لسياق الجهة وحالة الاتصال عند توفرها.
2. **الرأس:** Breadcrumb وعنوان/سياق الصفحة، مساحة لإجراءات عالمية محدودة، ومبدل اللغة وحساب المستخدم. يجب ألا ينافس الرأس إجراءات الصفحة.
3. **محتوى الصفحة:** خلفية عمل خفيفة، Header مؤسسي يضم العنوان وملخص السجل وأفعال الصفحة، ثم مناطق محتوى بترتيب: مؤشرات، مرشحات، جدول أو سجل، ثم تفاصيل داعمة.
4. **الهاتف:** يتحول التنقل إلى درج، وتتحول إجراءات Header إلى صف قابل للتمرير أو قائمة إجراءات؛ تبقى الإجراءات الحساسة نصية وليست أيقونة فقط.

## أنماط الصفحات

| نوع الصفحة | النمط المطلوب |
|---|---|
| قوائم الأصول والموظفين | شريط ملخص صغير، فلاتر واضحة، جدول ذو صفوف قابلة للمس، وشريط أفعال يظهر بعد التحديد. |
| البيانات الأساسية | شجرة أو قائمة مضغوطة، أفعال مرئية دائماً على اللمس، وحالة تعطيل مفهومة. |
| تفاصيل أصل | عنوان يحوي الكود والحالة وقيمة مختصرة وإجراء أساسي، ثم تبويبات بمحتوى لا يكرر البيانات. |
| الجرد والصيانة | تقدم سير عمل واضح، حالة الدورة/الأمر، ورسائل تأكيد تشرح الأثر ولا تكتفي بسؤال عام. |
| التقارير والتحليلات | ملخصات مرقمة ومرشحات قابلة للتتبع، ثم جدول/رسم؛ لا تستخدم رسوماً بلا سؤال عمل محدد. |

## الدفعة المرئية الأولى

تقتصر الدفعة الأولى على عناصر مشتركة ذات أثر واسع: `AppShell` و`Sidebar` و`Topbar` و`PageHeader` وأنماط الخلفية والبطاقات، ثم صفحات الأصول والبيانات الأساسية المتأثرة. لا تعاد كتابة كل صفحة في وقت واحد. بعد كل عنصر مشترك، يراجع البناء والاختبارات وصورة سطح المكتب والهاتف قبل الانتقال للعنصر التالي.
