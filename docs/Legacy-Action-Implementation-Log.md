# سجل تنفيذ إجراءات النظام السابق المكافئة — الدفعة الأولى

**تاريخ التنفيذ:** 15 أغسطس 2026  
**الهدف:** تطبيق الإجراءات ذات الأولوية من النظام السابق في منصة AssetX الحديثة، من دون إعادة استخدام WPF أو SQL Server أو الملفات التنفيذية القديمة.

## الإجراءات المنفذة

| المجال | الإجراء الحديث المنفذ | الحماية أو السلوك |
|---|---|---|
| قائمة الأصول | تعديل أصل واحد من الصف المحدد | يتطلب `asset.update` ويعيد استخدام نموذج الأصل الحالي. |
| قائمة الأصول | نسخ من أصل محدد | ينسخ الحقول التجارية، ويعيد الكمية إلى 1 ويمسح الباركود والرقم التسلسلي؛ تولد الأكواد في الخادم. |
| نموذج الأصل | تراجع عن التغييرات | يعيد حقول نموذج التعديل إلى لقطة الأصل المفتوح من دون حفظ تلقائي. |
| قائمة الأصول | تعديل جماعي | يغير الموقع أو العهدة أو الحالة أو الملاحظات للسجلات المحددة، ويعرض نتيجة صريحة للأصول التي لم تعدل. |
| Backend للأصول | حذف ناعم | يعطل الأصل ولا يزيله فعلياً؛ يتطلب `asset.delete` ويسجل حدث تدقيق. |
| Backend للأصول | حماية الارتباطات | يمنع الحذف والتعديل الجماعي عندما يوجد سجل حركة أو جرد أو صيانة أو دورة جرد مفتوحة مرتبطة. |
| الموظفون | إضافة وتعديل وتعطيل | ترتبط الواجهة بعقود CRUD الموجودة، ويظهر التعطيل فقط مع `employee.delete` ويظل محمياً من Backend عند وجود أصول نشطة. |
| الأنواع والحالات | تحسين قابلية اكتشاف الأزرار | أصبحت أزرار الإضافة الفرعية وإعادة التسمية وتعديل الحالة مرئية على اللمس بدلاً من الاعتماد على المرور بالماوس. |

## الاختبارات المنفذة

| التحقق | النتيجة |
|---|---|
| Backend TypeScript build | ناجح. |
| اختبارات وحدة الأصول | 11 اختباراً ناجحاً، وتشمل الحذف الناعم ومنع حذف أصل مرتبط بحركة والتعديل الجماعي ورفض الطلب بلا حقل تعديل. |
| اختبارات واجهة الويب | 54 اختباراً ناجحاً في 8 ملفات. |
| بناء Webpack للإنتاج | ناجح؛ تم توليد 23 مساراً. |
| تحقق API حي | ناجح: إنشاء أصل اختباري، تعديل جماعي للملاحظات (`200`)، حذف ناعم (`200`) ثم قراءة الأصل النشط بعد الحذف (`404`). |

أظهر التحقق الحي في محاولته الأولى أن `GET /assets/:id` كان يعيد `200` مع قيمة فارغة بعد الحذف الناعم. عولج العقد في Controller ليعيد `404 / ASSET_NOT_FOUND`، ثم أُعيد البناء وإجراء الاختبار الحي بنجاح.

## عناصر مؤجلة عمداً

حذف الأصناف وحالات الأصول لم يضف في هذه الدفعة، لأن عقود Backend لا تتضمن بعد فحصاً مرجعياً يمنع حذف نوع أو حالة مرتبطين بأصول. كما لم ينفذ الاستيراد، ومنشئ التقارير، وإعدادات النسخ الاحتياطي كجزء من هذه الدفعة، إذ تتطلب مسارات تشغيل وتدقيق منفصلة كما هو موثق في تقرير مطابقة النظام السابق.
