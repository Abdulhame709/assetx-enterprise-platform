# تقييم ملف تنظيم واجهات التطبيقات

**التاريخ:** 2026-08-22  
**الحالة:** مراجعة قبل التنفيذ  
**القرار:** لا يُطبق المرفق حرفياً؛ يُستخدم كضابط لإعادة التنظيم البصري فقط.

## الحكم التنفيذي

المرفق مناسب كـ **قائمة حوكمة وتجربة مستخدم**، لكنه ليس خطة تنفيذ مباشرة لمشروع AssetX. أهم ما فيه متوافق مع المشروع: عدم تغيير Business Logic، عدم حذف الوظائف، إبقاء كل إجراء قابلاً للوصول، استعمال Progressive Disclosure بحذر، والحفاظ على الحالة والاستجابة للهاتف.

أما نقْل الخيارات الثانوية إلى صفحة Settings بشكل عام، أو إنشاء طبقات Dropdown/More في كل صفحة، فليس مناسباً حالياً. قد يؤدي ذلك إلى تكرار نقاط الوصول، وإخفاء وظائف محاسبية مهمة مثل الطباعة والتصدير، وإضافة عناصر تنقل لا تحتاجها المنصة. لذلك يكون القرار: **تطبيق التنظيم الآمن فقط عندما يقلل التزاحم فعلاً، مع إبقاء الإجراءات الأساسية ظاهرة وعدم نقل CRUD إلى Settings**.

## مقارنة المتطلبات مع AssetX

| توصية المرفق | حالة AssetX الحالية | القرار | سبب القرار |
|---|---|---|---|
| عدم حذف أو تعطيل الوظائف أو تغيير backend/API | متوافق مع قواعد المشروع؛ الإجراءات الحالية متصلة بعقود حقيقية | يعتمد بالكامل | يحمي التوافق والتدقيق ولا يحتاج تغييراً. |
| إبقاء الوظائف الأساسية ظاهرة | `CommandToolbar` يعرض الأوامر الأساسية كأيقونات مع `title` و`aria-label` | يعتمد | يناسب أنظمة ERP والهاتف، خصوصاً البحث والإضافة والطباعة والتصدير. |
| نقل كل الخيارات الثانوية إلى Settings | صفحة Settings الحالية تحتوي إعداد اللغة فقط | يُرفض بصيغته العامة | نقل إجراءات السجل إلى Settings سيخلط إعدادات النظام بعمليات الأصول والحركات، وقد يجعل الوصول غير بديهي. |
| تجميع الخيارات الكثيرة في More/Accordion/Dropdown | بعض الصفحات تملك مجموعات كثيفة، لكن عدد الأوامر الأساسي محدود | يعتمد انتقائياً | يستخدم فقط للمجموعات الثانوية بعد التأكد من بقاء الوصول والتلميحات وعدم إخفاء الطباعة أو التصدير. |
| Progressive Disclosure | مطبق جزئياً عبر شريط الأوامر ومصمم التقارير والفلاتر القابلة للإظهار | يعتمد مع ضبط | نُبقي الأوامر المتكررة ظاهرة، ونخفي فقط الأدوات المساعدة أو الفلاتر الموسعة عندما لا تكون نشطة. |
| أيقونات مع tooltip | مطبق في شريط الأوامر ومعظم إجراءات الصفوف | يعتمد ويُستكمل | يجب ضمان `title` و`aria-label` وfocus ring لكل زر أيقوني. |
| Responsive Desktop/Tablet/Mobile | توجد تخطيطات متجاوبة للجرد والأصول والتقارير وشريط أوامر أفقي | يعتمد | يستمر تحسين المسافات والأحجام دون إنشاء شاشات مكررة. |
| الحفاظ على state | البحث والفلاتر والقوالب والجرد تعتمد على state حقيقي | يعتمد كشرط اختبار | أي نقل بصري يجب ألا يعيد تعيين البحث أو الفلاتر أو بيانات النموذج. |
| إضافة وظائف جديدة ممنوعة | ميزة AI وERP reports منفذة كوظائف حقيقية مستقلة | يعتمد | لا نضيف ميزات جديدة من هذا المرفق؛ نعيد ترتيب الموجود فقط. |

## خريطة التنظيم الآمن المقترحة

| الصفحة | يبقى ظاهراً | يمكن تجميعه لاحقاً | لا يُنقل إلى Settings |
|---|---|---|---|
| الأصول | البحث، الإضافة، التعديل، المعاينة، النسخ، التصدير، PDF، الطباعة | الفلاتر الموسعة وإجراءات التحديد الجماعي إذا زاد عددها | التعديل والحذف والتصدير والطباعة. |
| المواقع | البحث، تحديث، إضافة موقع رئيسي، طباعة، استيراد | إجراءات الصف الفرعية داخل شجرة الموقع | الإضافة والتعديل والحذف. |
| أنواع الأصول والحالات | البحث، تحديث، إضافة، طباعة، استيراد | إجراءات الصف الأيقونية موجودة في الصف | إنشاء وتعديل وتعطيل السجلات. |
| الموظفون | البحث، إضافة، تحديث، طباعة، استيراد | لا حاجة حالياً لقائمة More | تعديل وتعطيل الموظف. |
| الجرد | تحديث، طباعة، إنشاء دورة، فتح الدورة | إجراءات المزامنة والإغلاق داخل شاشة الدورة حسب الحالة | بدء الدورة وإغلاقها والمزامنة. |
| الحركات | تحديث، تصدير CSV/PDF، طباعة، مسح الفلاتر | الفلاتر المتقدمة إن زادت، مع إبقاء حالة الحركة واضحة | اعتماد ورفض ومعاينة الحركة. |
| التقارير | التصدير، الطباعة، مصدر التقرير، الصيغة، المصمم، ملخص AI | حفظ/استعادة التخطيط وقوالب التقرير يمكن تنظيمها داخل أقسام المصمم | التصدير والطباعة والتجميع والفرز. |

## نقاط التكرار أو التكدس التي وجدها التدقيق

يوجد تكرار سابق في مسح البحث بصفحة الموظفين؛ يوجد أمر مسح في شريط الأوامر وعملية مسح أخرى داخل بطاقة البحث. تمت إزالة الإجراء الداخلي المكرر مع إبقاء وظيفة المسح في شريط الأوامر.

توجد أزرار صفية كانت نصية في الأصول والموظفين، بينما صفحات المواقع والحالات وأنواع الأصول تستخدم أيقونات. تم توحيد الإجراءات التي تناسب الأيقونات مع الإبقاء على النصوص في الأفعال الأولية التي تحتاج وضوحاً عالياً، مثل أزرار النماذج والتأكيد.

يُستخدم `CommandToolbar` كنقطة الوصول الموحدة. لذلك لا ينبغي إنشاء شريط ثانٍ لنفس أوامر البحث والتحديث والطباعة والتصدير في الصفحة ذاتها.

## مخاطر التطبيق الحرفي

| الخطر | النتيجة المحتملة | المعالجة |
|---|---|---|
| نقل الأوامر إلى Settings | المستخدم لا يجد التعديل أو التصدير في سياق السجل | إبقاء إجراءات السجل بجانب السجل أو في شريط الصفحة. |
| إخفاء الطباعة أو PDF داخل More | مخالفة احتياج المستخدم السابق للتقارير والطباعة | إبقاء الطباعة والتصدير الأساسي ظاهراً. |
| إنشاء Dropdown في كل صفحة | تكدس مكونات جديدة وتعقيد الهاتف والاختبار | لا يضاف إلا عندما يوجد ازدحام مثبت. |
| إزالة النص من كل الأزرار | ضعف فهم الأفعال الخطرة مثل التعطيل أو الحذف | الأيقونة مع tooltip للأفعال المتكررة، والنص للأفعال الحساسة أو الأولية عند الحاجة. |
| إعادة تركيب المكونات أثناء النقل | فقدان state للفلاتر والنماذج | تعديل موضعي واختبارات regression لكل حالة. |
| جعل الأزرار مخفية بالـhover فقط | اختفاؤها على الهاتف أو صعوبة الوصول بلوحة المفاتيح | `focus-within` وظهور دائم على أجهزة اللمس؛ وهو نمط مطبق في شجرة المواقع. |

## قرار التنفيذ

لا نطبق المرفق كإعادة بناء شاملة ولا ننشئ Settings جديدة لمجرد إخفاء الأوامر. الدفعة الآمنة هي تحسينات UI موضعية فقط: توحيد الأيقونات والتلميحات، إزالة التكرار، ضبط الأحجام للهاتف، وإضافة تجميع محدود للفلاتر أو إعدادات المصمم إذا أثبت الفحص وجود تزاحم.

لا يتضمن هذا القرار أي تغيير في backend أو قاعدة البيانات أو API أو الصلاحيات أو Business Logic. كما لا يضيف ميزات جديدة. أي تغيير لاحق يجب أن يمر عبر TypeScript واختبارات الواجهة وبناء الإنتاج ومراجعة مرئية للهاتف.
