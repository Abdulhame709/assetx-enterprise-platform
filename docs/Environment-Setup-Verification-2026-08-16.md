# تقرير إعداد بيئة التشغيل وقاعدة البيانات

> **المنصّة:** AssetX Enterprise Platform
> **التاريخ:** 16 أغسطس 2026
> **الفرع المرجعي:** `main`
> **الالتزام المرجعي:** `48faaee`
> **نوع البيئة:** تحقق محلي مع PostgreSQL حقيقي؛ ليست بيئة staging أو إنتاج منشورة
> **الحالة:** مكتمل محلياً، ومتوقف خارجياً على بيانات مزود الاستضافة وأسرار الإنتاج

## 1. نطاق التنفيذ

تم تنفيذ الجزء القابل للتنفيذ داخل بيئة العمل الحالية من المرحلة الأولى. شمل ذلك تثبيت PostgreSQL 16 وعميل `psql`، إنشاء قاعدة `assetx`، فصل حساب الترحيلات عن حساب تشغيل التطبيق، تطبيق الترحيلات الرسمية عبر منفذ `backend/dist/bootstrap/migrate.js`، تجهيز مستأجرين للتحقق، تشغيل بيانات seed، إضافة seed idempotent لكتالوج الصلاحيات، ثم تشغيل Backend وWeb محلياً واختبار البروكسي والصحة والمصادقة والعزل بين المستأجرين.

لم يتم نشر أي خدمة خارجية، ولم تُستخدم أسرار إنتاجية أو بيانات حقيقية. ملفات البيئة المحلية التي تحتوي على كلمات مرور ومفاتيح JWT حُفظت خارج المستودع في `/home/ubuntu/assetx-runtime/`، بينما أُضيفت إعدادات الواجهة غير السرية فقط إلى `web/.env.local`، وهو ملف مستبعد من Git.

## 4. نتائج الاختبارات والتشغيل الحي

اجتاز Backend البناء واختبارات Jest الكاملة: **48 مجموعة اختبار و318 اختباراً ناجحاً**. تعذر تشغيل أمر `npm run lint` للخلفية لأن حزمة Backend لا تحتوي على `eslint` ضمن اعتمادياتها الحالية؛ لم تُعدّل الاعتماديات تلقائياً حتى لا يتغير lockfile دون قرار مستقل.

اجتازت Web اختبارات Vitest: **9 ملفات و57 اختباراً ناجحاً**. نجح بناء Web الإنتاجي وولّد **23 مساراً**. أمر lint للواجهة لم ينتج أخطاء، لكنه أصدر **16 تحذيراً** من قاعدة `react-hooks/set-state-in-effect` في ملفات الواجهة؛ هذه التحذيرات لا تمنع البناء لكنها تسجل كدين جودة لاحق.

## 5. التغييرات الموثقة في المستودع

أضيف `db/seed/002_permissions.sql` لتهيئة الصلاحيات وربطها بالأدوار بصورة قابلة للتكرار. حُدّث `db/README.md` لشرح ملف seed الجديد وسياق `app.tenant_id`. حُدّث `ops/staging/README.md` ليشمل ربط حساب التشغيل بدور `authenticated` وتسلسل seed الصلاحيات بعد seed البيانات الأساسية. لم تُحفظ أي كلمات مرور أو مفاتيح JWT في المستودع.

## 6. ما لم يُنفذ بعد

لا توجد بيانات اعتماد لمزود PostgreSQL مُدار أو مزود الاستضافة في الجلسة الحالية، لذلك لم يتم تنفيذ نشر staging خارجي، ولم تُطبّق الترحيلات على Supabase أو RDS أو أي قاعدة خارجية. كذلك لم يتم إنشاء حساب secret manager أو ضبط نطاق `CORS_ORIGIN` الإنتاجي.

لإغلاق بوابة النشر الخارجية، يلزم توفير مزود الاستضافة، عنوان PostgreSQL عبر TLS، اسم قاعدة/حساب runtime، نطاق Web النهائي، وقيم `JWT_ACCESS_SECRET` و`JWT_REFRESH_SECRET` عبر مخزن أسرار. بعدها تُجرى تهيئة دور runtime، الترحيلات كـ job منفصل، seed داخل سياق tenant، اختبار دخان، ثم backup/restore smoke test على قاعدة استعادة مؤقتة.

## 7. ملاحظات تشغيلية

الخدمات الحالية تعمل داخل البيئة المحلية الحالية فقط، وقد تتوقف عند إيقاف البيئة أو سباتها. لا ينبغي اعتبار `127.0.0.1` أو كلمات المرور المحلية إعداداً صالحاً للإنتاج. كما يجب عدم تشغيل `RUN_MIGRATIONS=true` داخل خدمة Backend الإنتاجية؛ تبقى الترحيلات مهمة منفصلة ومراجعة مع نسخة احتياطية قبل تغييرات Schema.
